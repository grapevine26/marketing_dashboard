# 인수인계 문서

RB Global 마케팅 운영 플랫폼을 넘겨받는 개발자를 위한 문서입니다.
**5장 "건드리면 사고 나는 곳"은 코드를 고치기 전에 읽어주세요.** 나머지는 필요할 때 찾아보시면 됩니다.

작성 2026년 9월 15일

---

## 1. 이게 뭔가

인플루언서 마케팅 대행사의 내부 업무 도구입니다. 대행사 직원이 로그인해서 쓰고, 광고주와 인플루언서는 로그인 없이 **공유 링크**로 들어옵니다.

업무가 세 갈래입니다.

- **인플루언서 시딩** 캠페인을 만들고 지원을 받아 선정하고, 배송·업로드 진행을 관리시트로 추적하고, 결과보고서를 PDF·PPT로 뽑습니다.
- **오프라인 행사** 초청자 명단, 준비 체크리스트, 행사 운영안 PPT입니다.
- **SNS 채널 운영** 콘텐츠 캘린더를 만들고 광고주에게 시안 승인을 받습니다.

여기에 계정·권한 관리와 활동 기록이 붙습니다.

**규모**: 앱 코드 29,000줄, 화면 33개, 서버 기능 77개, 데이터베이스 표 23개, 자동 테스트 242개.

**현재 상태**: 2026년 9월 15일 실사용 시작. 업무 데이터는 아직 없습니다.

## 3. 시작하기

```bash
npm ci
cp .env.local.example .env.local   # 값을 채워야 합니다
npm run dev                        # http://localhost:3000
```

### 환경변수

`.env.local` 에 넣습니다. 배포는 Vercel 프로젝트 설정에 있습니다.

| 이름 | 용도 | 없으면 |
|---|---|---|
| `SUPABASE_URL` | 운영 프로젝트 API 주소 | 모든 기능이 오류 |
| `SUPABASE_SERVICE_ROLE_KEY` | 서버 전용 키 | 모든 기능이 오류 |
| `SUPABASE_ANON_KEY` | 로그인용 | 로그인 불가 |
| `SUPABASE_DB_URL` | 마이그레이션·백업 스크립트용 | 스크립트만 안 됨 |
| `SUPABASE_TEST_*` | 테스트 전용 프로젝트 (4개) | 테스트가 통째로 건너뜀 |
| `CRON_SECRET` | 백업 크론 인증 | 백업이 503으로 닫힘 |
| `GEMINI_API_KEY` | AI 초안 | AI만 안내 문구로 대체 |
| `BLOB_READ_WRITE_TOKEN` | 파일 저장소 (Vercel이 자동 주입) | 로컬 디스크로 대체 |

**Supabase 프로젝트가 두 개입니다.** 운영과 테스트입니다. 테스트 쪽은 테스트가 돌 때마다 모든 표를 비우므로 절대 섞이면 안 됩니다. 5장을 보세요.

**DB 주소는 Session pooler 문자열이어야 합니다.** Supabase 대시보드에서 `db.<ref>.supabase.co` 로 시작하는 직접 연결 주소를 주는데, 그건 IPv6 전용이라 대부분의 환경에서 안 붙습니다.


## 4. 구조

### 폴더

```
app/(dashboard)/   로그인이 필요한 화면. layout.tsx 가 requireUser() 로 지킨다
app/apply/[token]/         공개: 인플루언서 지원폼
app/pre-survey/[token]/    공개: 광고주 사전조사
app/applicants/[token]/    공개: 광고주 지원자 확인·선정
app/seeding-sheet/[token]/ 공개: 광고주 진행현황 조회
app/sns-approval/[token]/  공개: 광고주 시안 승인
app/sns-intake/[token]/    공개: 광고주 채널 정보 제출
app/signup/[token]/        공개: 초대 링크로 들어오는 가입
app/api/                   파일 내려받기·업로드, 백업 크론

lib/db/        데이터 계층. 도메인별 파일 하나씩
lib/auth/      로그인·권한·초대
lib/actions/   서버 액션 공통 래퍼
lib/security/  시도 제한
lib/ppt/       PPT 템플릿 엔진
lib/reports/   PDF·PPTX 생성
proxy.ts       로그인 검사 바깥 겹 (옛 middleware.ts)
supabase/migrations/  번호 순서대로 적용되는 SQL
```

### 데이터가 흐르는 길

```
화면 (클라이언트 컴포넌트)
  → 서버 액션 (app/**/actions.ts)
    → 래퍼 (lib/actions/result.ts) ─ 여기서 로그인·등급을 검사한다
      → 데이터 계층 (lib/db/*.ts) ─ 검증하고 DB 에 쓰고 감사 로그를 남긴다
        → Supabase
```

**API 라우트를 따로 만들지 않습니다.** 파일을 내려받거나 올릴 때만 `app/api/` 를 씁니다. 나머지는 전부 서버 액션입니다.

### 서버 액션 규칙

`lib/actions/result.ts` 에 래퍼가 넷 있습니다. **모든 액션은 이 중 하나로 시작해야 합니다.**

| 래퍼 | 통과 조건 |
|---|---|
| `runAction` | 없음. 공개 링크 전용 |
| `runAuthedAction` | 승인된 계정 |
| `runAdminAction` | 관리자 이상 |
| `runOwnerAction` | 대표 관리자만 |

**규칙: 액션 함수 본문의 첫 문장은 `return run…Action(...)` 이어야 합니다.** 래퍼 바깥에서 DB를 조회하거나 파일을 처리하면 로그인하지 않은 사람도 그 코드를 실행시킬 수 있습니다. 실제로 그런 구멍이 있었고 2026년 9월 15일에 전부 안으로 옮겼습니다.

### 인증 모델

**이메일을 쓰지 않습니다.** 아이디만 씁니다. Supabase Auth 가 이메일 기반이라 내부적으로 `<아이디>@moa.local` 이라는 가짜 주소로 저장합니다. 사용자는 이 주소를 보지도 입력하지도 않습니다.

> `moa.local` 은 옛 서비스 이름(MOA)의 흔적입니다. **바꾸지 마세요.** 기존 계정이 전부 이 주소로 저장돼 있어서 바꾸면 아무도 로그인하지 못합니다. 사용자에게 보이지 않는 값입니다.

검사가 두 겹입니다.

1. `proxy.ts` 가 쿠키에 세션이 있는지만 봅니다. DB는 안 봅니다. 모든 요청마다 돌기 때문에 빨라야 합니다.
2. `lib/auth/session.ts` 가 DB를 보고 진짜 판정합니다. 여기가 실제 경계입니다.

| 가드 | 쓰는 곳 |
|---|---|
| `requireUser()` | 화면·서버 액션. 실패하면 리다이렉트 |
| `requireApiUser()` | `route.ts`. 실패하면 401/403 JSON |
| `requireAdmin()` | 관리 화면 |
| `requireOwner()` | 활동 기록, 등급 변경 |

**`route.ts` 는 레이아웃을 거치지 않습니다.** 그래서 반드시 `requireApiUser()` 를 직접 불러야 합니다. 안 부르면 가입만 한 사람도 파일을 받아갑니다. `tests/unit/auth.test.ts` 에 이걸 잡는 구조 테스트가 있습니다.

### 등급

`owner` (대표 관리자) / `admin` (관리자) / `staff` (직원) 셋입니다. `lib/auth/roles.ts` 에 정의가 있고, 클라이언트 컴포넌트도 써야 해서 `server-only` 가 아닌 파일에 따로 두었습니다.

잠기지 않도록 막아둔 규칙들이 `lib/auth/users.ts` 에 있습니다. 마지막 대표 관리자는 강등·차단·삭제가 안 되고, 자기 자신도 차단·삭제할 수 없습니다.

### 가입

**초대 링크로만 됩니다.** 대표 관리자가 사람마다 링크를 만들고, 링크는 계정이 만들어지는 순간 죽습니다. 기한은 72시간입니다. `lib/auth/invites.ts` 를 보세요.

가입해도 바로 못 씁니다. 관리자가 승인해야 합니다.

### 공유 링크

캠페인과 SNS 계정마다 무작위 토큰이 있고, 그 토큰이 주소에 들어갑니다. 재발급하면 옛 링크는 즉시 죽습니다.

**캠페인이 `completed` 이거나 SNS 계정이 `ended` 면 링크가 닫힙니다.** 화면·서버 액션·파일 내려받기 세 곳에서 모두 막습니다.

## 5. 건드리면 사고 나는 곳

**이 장만은 코드를 고치기 전에 읽어주세요.**

### 5-1. 테스트가 데이터베이스를 통째로 비웁니다

`tests/unit/setup.ts` 가 **매 테스트마다** 모든 표를 truncate 하고 `auth.users` 를 지웁니다.

대상이 운영이면 서비스가 사라집니다. 그래서 `tests/unit/test-db.ts` 에 3중 가드가 있습니다. 테스트 주소와 운영 주소에서 프로젝트 ref 를 뽑아 교차 대조하고, 하나라도 겹치면 즉시 멈춥니다.

**이 가드를 우회하지 마세요.** 과거에 실제로 위험했던 경로입니다. 가드가 API 주소만 비교하고 정작 truncate 는 DB 주소로 접속하고 있었습니다. 두 문자열은 ref 한 조각만 달라서 잘못 붙여넣기 쉽습니다.

**단위 테스트와 e2e 를 동시에 돌리지 마세요.** 같은 테스트 DB를 쓰기 때문에 서로의 데이터를 지웁니다. CI 에서는 순서를 세워뒀습니다.

### 5-2. 개인정보 세척 함수가 두 개입니다

광고주 공유 화면에 데이터를 내보낼 때 씁니다. `lib/db/types.ts` 에 있습니다.

- `sanitizeApplicantForCompany` — 지원자의 연락처·주소·내부 메모를 비웁니다
- `sanitizeSeedingForCompany` — 시딩 기록의 배송지·방문일정·내부 비고를 비웁니다

**둘 다 써야 합니다.** 관리시트 한 줄은 지원자와 시딩 기록이 합쳐진 것이고, **배송지는 양쪽에 따로 들어 있습니다.** 한쪽만 씻으면 다른 쪽으로 샙니다. 실제로 그 상태로 배포돼 있었습니다.

화면에 안 그려도 서버가 내려보내면 페이지 안에 값이 실립니다. 화면에서 안 보인다고 안전한 게 아닙니다.

`tests/unit/security_fixes.test.ts` 가 이걸 검사합니다.

### 5-3. 백업이 유일한 방어선입니다

**Supabase 무료 요금제에는 자동 백업이 없습니다.** 매일 새벽 3시(KST)에 도는 우리 크론이 전부입니다. Vercel Blob 의 `backups/` 에 쌓이고 최근 30개만 남습니다.

- 백업에 **들어가는 것**: 모든 업무 데이터, 활동 기록, 계정 정보(아이디·이름·등급·승인 상태)
- 백업에 **안 들어가는 것**: 로그인 비밀번호(Supabase만 보관), 업로드한 파일

비밀번호를 안 넣는 것은 의도한 것입니다. 파일로 빼두면 그 파일이 새로운 위험이 됩니다.

자세한 절차는 `docs/ops-backup.md` 에 있습니다.

### 5-4. 공유 클라이언트로 로그인하지 마세요

`getAdminClient()` 로 얻은 클라이언트에 `auth.signInWithPassword()` 를 호출하면 **그 클라이언트의 권한이 로그인한 사용자 것으로 바뀝니다.** 이후 모든 조회가 조용히 막혀 빈 결과를 돌려줍니다. 오류도 안 납니다.

비밀번호 확인이 필요하면 매번 새 클라이언트를 만드세요. `lib/auth/profile.ts` 의 `changeMyPassword` 가 그 예입니다.

### 5-5. pg 로 날짜를 읽을 때

`pg` 는 `date` 컬럼을 Date 객체로 줍니다. 그대로 JSON 으로 쓰면 한국 시간 자정이 UTC 기준 전날이 되어 **왕복할 때마다 날짜가 하루씩 밀립니다.**

`scripts/db-backup.mjs` 가 `pg.types.setTypeParser(1082, v => v)` 로 막고 있습니다. `pg` 로 이 DB를 읽는 스크립트를 새로 만들면 같은 처리를 하세요.

### 5-6. 클라이언트 컴포넌트가 서버 모듈을 가져가면 빌드가 깨집니다

`lib/auth/session.ts`, `lib/auth/invites.ts` 등은 `import "server-only"` 입니다. `"use client"` 파일이 여기서 뭔가 가져오면 **타입 검사는 통과하고 `npm run build` 에서 터집니다.**

그래서 값과 타입만 따로 빼둔 파일이 있습니다. `lib/auth/roles.ts`, `lib/auth/invite-types.ts` 입니다. 클라이언트도 써야 하는 상수를 추가할 때는 이 패턴을 따르세요.

### 5-7. 감사 로그는 삭제보다 먼저

무언가를 지울 때는 **지우기 전에** 감사 로그를 남깁니다. 대상이 사라진 뒤에는 이름을 쓸 수 없기 때문입니다.

`audit_logs` 표에는 외래키가 없습니다. 일부러 그렇게 했습니다. 캠페인을 지워도 "누가 언제 지웠다"가 남아야 합니다.

## 6. 자주 하게 될 작업

### 데이터베이스 컬럼 추가

1. `supabase/migrations/` 에 다음 번호로 SQL 파일을 만듭니다
2. `npm run db:migrate -- --test` 로 테스트 프로젝트에 먼저 적용
3. `lib/db/types.ts` 의 타입과 `lib/db/mappers.ts` 의 변환을 고칩니다
4. 광고주에게 보여도 되는 값인지 판단하고, 아니면 세척 함수에 추가합니다 (5-2)
5. `tests/unit/test-db.ts` 의 truncate 목록에 새 표가 있으면 추가
6. 배포 **전에** `npm run db:migrate` 로 운영에 적용

마이그레이션 스크립트가 적용 후 `notify pgrst, 'reload schema'` 를 보냅니다. 이게 없으면 새 컬럼이 안 보입니다.

### 화면 추가

`app/(dashboard)/` 아래에 만들면 레이아웃이 `requireUser()` 로 지킵니다. 사이드바 메뉴는 `app/(dashboard)/DashboardShell.tsx` 의 배열에 추가합니다.

### 서버 액션 추가

같은 폴더의 `actions.ts` 에 만들고, 첫 문장을 적절한 래퍼로 시작합니다. 데이터를 바꾸는 작업이면 `lib/db/` 쪽에서 `insertAuditLog` 를 부릅니다. 행위자 이름은 자동으로 채워집니다.

### 파일 내려받기 라우트 추가

`app/api/` 에 `route.ts` 를 만들고 **첫 줄에서 `requireApiUser()` 를 부릅니다.**

```ts
const auth = await requireApiUser();
if (auth instanceof NextResponse) return auth;
```

안 부르면 테스트가 실패합니다.

### 계정 관리

```bash
npm run db:make-admin <아이디>      # 대표 관리자로 올림
npm run db:hide-user <아이디>       # 사용자 관리 목록에서 숨김
npm run db:hide-user -- --list      # 숨긴 계정 목록
```

## 7. 배포

**main 에 푸시하면 Vercel 이 자동 배포합니다.**

순서가 중요합니다. **마이그레이션이 있으면 배포 전에 운영에 적용하세요.** 코드가 먼저 올라가면 없는 표를 찾다가 기능이 멈춥니다.

```bash
npm run db:migrate    # 먼저
git push              # 그다음
```

CI(`.github/workflows/ci.yml`)가 타입 검사, 린트, 단위 테스트, 빌드, e2e 를 돌립니다. **CI 실패가 배포를 막지는 않습니다.** Vercel 이 CI 결과를 기다리지 않습니다. 필요하면 Vercel 설정에서 바꿀 수 있습니다.

CI 에는 Supabase 테스트 프로젝트 키가 GitHub Secrets 로 들어가 있습니다. 운영 키 두 개도 있는데, 접속용이 아니라 "테스트 대상이 운영이 아님"을 대조하는 가드 전용입니다.

## 8. 테스트

| 종류 | 개수 | 명령 |
|---|---|---|
| 단위 | 191 | `npm test` |
| e2e | 49 | `npm run test:e2e` |

**둘을 동시에 돌리지 마세요.** 같은 테스트 DB를 비웁니다.

**테스트 DB에는 `public.test_db_marker` 테이블이 있어야 합니다.** 테스트는 매번 모든 테이블을
truncate 하므로, 대상이 테스트 DB임을 DB 안에서 직접 확인한 뒤에만 실행합니다. 환경변수끼리
비교하는 검사는 `.env.local` 을 통째로 운영 값으로 덮어쓰면 다 통과해버립니다. 표식이 없으면
한 줄도 지우지 않고 멈춥니다. 테스트 프로젝트를 새로 만들었다면 SQL 편집기에서 한 번:

```sql
create table public.test_db_marker (note text);
alter table public.test_db_marker enable row level security;
```

e2e 는 `tests/e2e/global-setup.ts` 가 매번 테스트 DB를 비우고, 전용 계정을 만들어 실제로 로그인하고, 시드 데이터를 넣습니다.

**공개 링크 검증은 쿠키 없는 브라우저로 합니다.** 로그인한 상태로 확인하면 "로그인 없이도 열리는가"를 검증하지 못합니다. 실제로 이 때문에 개인정보 유출을 놓치고 있었습니다. 공개 화면 테스트를 추가할 때는 `NO_AUTH` 를 쓰세요.

테스트는 왜 그렇게 동작해야 하는지를 한국어로 설명해두었습니다. 기대 동작을 알고 싶으면 테스트 이름을 읽는 게 빠릅니다.

## 9. 알려진 한계

### 구조상 그런 것 (고칠 계획 없음)

**회사 한 곳을 위한 구조입니다.** 조직을 나누는 칸이 없습니다. 다른 대행사가 쓰려면 서버를 하나 더 띄우는 방식이 됩니다. 서너 곳까지는 그게 오히려 간단하고 안전합니다.

**관리자가 남의 비밀번호를 초기화해도 그 사람의 다른 기기 세션은 끊지 못합니다.** 그 사람의 토큰이 필요한데 관리자는 갖고 있지 않습니다. 계정을 빼앗긴 것으로 의심되면 초기화만 하지 말고 **차단했다가 다시 푸세요.** 차단이 인증 계정을 잠가 세션을 전부 끊습니다.

**업로드한 파일은 백업되지 않습니다.** 시안 이미지와 PPT 템플릿입니다. DB 백업에는 파일을 가리키는 주소만 들어갑니다.

**대표 관리자가 실질적으로 한 명입니다.** 그 사람이 비밀번호를 잊으면 풀어줄 사람이 없습니다. 직원 한 명을 대표 관리자로 더 올려두는 편이 안전합니다.

### 아직 고치지 않은 것

여기 적힌 것은 **알고 있으면서 고치지 않은** 항목입니다. 인수받는 쪽이 모르고 밟으면 곤란한 것들이라 숨기지 않고 적어둡니다.

| 항목 | 무슨 일이 생기나 | 왜 두었나 |
|---|---|---|
| **CSP 에 `script-src` 가 느슨합니다** | XSS 가 생겼을 때 인라인 스크립트를 막지 못합니다 | nonce 를 붙이려면 이 버전 Next.js 의 스트리밍 렌더와 맞물려 화면이 깨질 위험이 있습니다. 공개 직전에 손대기에는 위험 대비 이득이 작다고 판단했습니다. 입력값은 전부 React 가 escape 하고, 사용자가 HTML 을 넣는 칸은 없습니다 |
| **공용 질문 템플릿은 동시 수정에 약합니다** | 두 사람이 사전조사/SNS 질문 템플릿을 같은 시각에 고치면 나중에 저장한 쪽이 이깁니다 | 캠페인·지원자 같은 주요 데이터에는 낙관적 잠금(`lib/db/optimistic-lock.ts`)이 걸려 있지만 템플릿에는 없습니다. 쓰는 사람이 서너 명이라 실제로 부딪힐 일이 드뭅니다. 고친다면 같은 잠금을 붙이면 됩니다 |
| **사전조사 응답은 캠페인당 1건입니다** | 같은 링크로 다시 제출하면 이전 답변이 덮어써집니다 | 원래 의도된 동작입니다(오타 수정). 다만 이전 답이 남지 않으므로, **덮어쓴 사실을 감사 로그에 남기도록** 했습니다(`pre_survey.resubmitted`). 이전 답변 본문까지 보관하려면 응답 테이블을 이력형으로 바꿔야 합니다 |
| **의존성에 중간 등급 취약점 2건** | 실제로 닿는 경로는 없습니다 | exceljs 가 쓰는 uuid 인데, 취약 조건에 해당하는 사용법이 아닙니다. 상위 패키지가 올라가면 자연히 사라집니다 |
| **린트 경고 12건** | 없습니다 | 안 쓰는 import 와 `<img>` 대신 `next/image` 권고입니다. 오류는 0건입니다 |
| **업로드 파일 백업 없음** | 위 "구조상 그런 것" 참고 | 시안 이미지는 승인이 끝나면 가치가 크게 떨어지고, 용량이 DB 보다 훨씬 큽니다 |

### 이미 막아둔 것 (다시 열지 마세요)

되돌리기 쉬운 자리라 적어둡니다. 자세한 이유는 코드 주석에 있습니다.

- **`proxy.ts` 의 `PUBLIC_PREFIXES` 항목은 반드시 `/` 로 끝나야 합니다.** `/apply` 로 적으면 `/applicants-secret` 같은 주소까지 열립니다. 이 규칙은 `tests/unit/security_fixes.test.ts` 가 지킵니다.
- **공개 경로에 지원자 원본을 그대로 돌려주지 마세요.** 광고주에게 나가는 값은 전부 `sanitizeApplicantForCompany()` 를 거칩니다. 화면·서버 액션·CSV 세 곳에서 같은 실수가 세 번 났습니다.
- **횟수 제한은 DB(`auth_throttle`)로 셉니다.** 메모리에 세면 서버리스에서는 요청마다 비워져 아무것도 막지 못합니다. `lib/security/rateLimit.ts` 는 그래서 지웠습니다.
- **백업 대상 테이블을 늘릴 때는 `BACKUP_TABLES` 와 `ORDER_COLUMN` 을 함께** 고치세요. 하나만 고치면 백업 전체가 실패합니다.
