# 대시보드에서 실행하는 SQL 통합본

`supabase/migrations/`의 마이그레이션을 순서대로 이어붙인 파일들입니다. **원본이 아니라 사본**이므로, 스키마를 고칠 때는 항상 `supabase/migrations/`쪽을 고치고 여기를 다시 생성하세요.

## 왜 있는가

이 저장소에서는 Supabase CLI가 인증돼 있지 않고 DB 비밀번호도 없어서 `supabase db push`나 `migration up`을 쓸 수 없습니다. 그래서 마이그레이션을 Supabase 대시보드 → SQL Editor에 직접 붙여넣어 적용합니다. 파일 하나로 합쳐두면 아홉 번 왕복할 일을 한 번에 끝낼 수 있습니다.

## 파일

| 파일 | 담긴 마이그레이션 | 상태 |
|---|---|---|
| [setup-0001-0005.sql](setup-0001-0005.sql) | profiles, campaigns, 사전조사 3종 | 적용 완료 (2026-08-30) |
| [setup-0006-0014.sql](setup-0006-0014.sql) | 신청폼·지원자, 선정, 관리시트, 보고서 (서브프로젝트 A) | **적용 대기 — 1순위** |
| [setup-0015-0021.sql](setup-0015-0021.sql) | PPT 템플릿 엔진, 행사(B), SNS 운영(C) | **적용 대기 — 2순위** |

D(오버뷰)는 다른 서브프로젝트의 데이터를 읽기만 하므로 마이그레이션이 없습니다.

**반드시 위 순서대로 실행하세요.** 0015~0021은 0006~0014가 만드는 `applicants` 테이블을 참조합니다.

## 적용 방법

1. Supabase 대시보드 → SQL Editor
2. 해당 파일 전체를 붙여넣고 실행
3. 로컬에서 `npm test`로 DB 테스트 검증

이미 적용한 파일을 다시 실행하면 `already exists` 오류가 납니다. 순서대로 한 번씩만 실행하세요.

## 다시 생성하려면

```bash
{ for f in supabase/migrations/00{06,07,08,09,10,11,12,13,14}_*.sql; do
    echo "-- ============================================"
    echo "-- $(basename $f)"
    echo "-- ============================================"
    cat "$f"; echo ""
  done
} > docs/sql/setup-0006-0014.sql
```

0015~0021 번들은 같은 방식으로 번호만 바꿔 생성합니다.

```bash
{ for f in supabase/migrations/00{15,16,17,18,19,20,21}_*.sql; do
    echo "-- ============================================"
    echo "-- $(basename $f)"
    echo "-- ============================================"
    cat "$f"; echo ""
  done
} > docs/sql/setup-0015-0021.sql
```
