# 인플루언서 시딩 관리 (서브 프로젝트 A) 설계

- 작성일: 2026-08-30 (2026-08-30 개정: 지원자리스트/관리시트 외부공유, 예비선정, PPT 보고서 추가)
- 상태: 승인됨 (브레인스토밍 완료, 구현 계획 수립 단계로 진행)

## 배경 및 범위

이 문서는 인플루언서 마케팅 에이전시용 통합 대시보드의 4개 서브 프로젝트(A: 인플루언서 시딩, B: 인플루언서 행사, C: SNS 운영, D: 오버뷰/전체일정) 중 **A. 인플루언서 시딩 관리**의 설계다.

전체 워크플로우: 업체정보 사전조사 → 신청폼 배포 → 지원자 리스트 자동 정리 → 최종선정 → 관리시트 자동생성 → 결과보고서 자동생성.

B/C/D는 이 스펙의 범위가 아니며, A 구현 이후 각각 별도 브레인스토밍 → 스펙 → 계획 사이클을 거친다.

## 아키텍처

- **프론트/백엔드**: Next.js (App Router). API Routes/Server Actions로 서버 로직 처리.
- **DB/Auth**: Supabase (Postgres + Supabase Auth).
- **배포**: Vercel.
- **AI 연동**: 사전조사 답변 어시스트, 신청폼 소개문구 초안 생성용 LLM API 호출은 서버 사이드에서만 수행 (클라이언트에 API 키 노출 금지).
- **라우팅 구조**: 하나의 Next.js 프로젝트 안에 두 영역이 공존한다.
  - **공개 영역** (로그인 불필요, 캠페인별 고유 토큰으로 접근):
    - `/pre-survey/[token]` (업체 사전조사)
    - `/apply/[token]` (지원자 신청폼)
    - `/applicants/[token]` (지원자 리스트 공유 페이지 — 최종선정/예비선정 액션 포함)
    - `/seeding-sheet/[token]` (관리시트 공유 페이지 — 조회 전용)
  - **내부 대시보드 영역** (Supabase Auth 로그인 필요): 캠페인 관리, 지원자 리스트, 관리시트, 보고서 생성

캠페인별로 위 4개 용도의 토큰을 각각 독립적으로 발급한다 (하나의 토큰을 공유하지 않음 — 용도별 링크를 따로 배포/회수할 수 있도록).

## 데이터 모델

### `profiles`
Supabase Auth 사용자와 1:1. `role` (`admin` | `staff`).

### `campaigns`
- 캠페인 기본정보: 이름, 업체명, 캠페인 유형 (`shipping` 제품배송형 | `visit` 현장방문형), 상태
- 공개 접근용 고유 토큰 4개: 사전조사용, 신청폼용, 지원자리스트 공유용, 관리시트 공유용
- `created_by`, `created_at`

### `pre_survey_template`
- 에이전시가 사전 설정하는 질문틀 (JSONB, 질문 배열). 전역 설정 1개, **admin만 수정 가능**.

### `pre_survey_responses`
- `campaign_id` FK, 답변 (JSONB), 작성 주체 (`company` | `agency`), AI 어시스트 사용 여부, `submitted_at`

### `campaign_form_config`
- `campaign_id` FK, 소개문구 (AI 초안 → 담당자 수정), 커스텀 질문 목록 (JSONB), 공개 여부

### `applicants`
- `campaign_id` FK
- 표준 필드 (실제 컬럼): 이름, SNS 계정 링크, 국적, 연락처, 개인정보 수집 동의 여부, 2차활용 동의 여부
- 커스텀 문항 답변 (JSONB, `campaign_form_config`의 커스텀 질문에 대응)
- 상태: `applied` | `selected`(최종선정) | `reserved`(예비선정) | `rejected`
- `applied_at`
- `status_changed_by` (`agency` | `company`), `status_changed_at` — 최종선정/예비선정 액션의 실행 주체·시각 기록 (감사 추적용)

상태 전이: `applied` → `selected` 또는 `reserved` (에이전시 내부 또는 업체 담당자가 공유 링크에서 동일하게 실행 가능, 액션 주체와 무관하게 결과 즉시 반영) → `reserved`에서 `selected`로 승격 가능(예비→최종). `selected`로 전이되는 순간에만 아래 `seeding_records`가 생성된다. `reserved` 상태는 지원자 리스트에만 표시되고 관리시트에는 포함되지 않는다.

### `seeding_records`
`applicants`가 `selected` 상태가 되는 시점에 1건 생성 (1:0..1 관계). 예비선정(`reserved`) 단계에서는 생성되지 않는다.
- `applicant_id` FK, `campaign_id` FK
- 제품배송형 전용: 배송 주소
- 현장방문형 전용: 방문 일정, 방문 인원
- 진행 단계 (캠페인 유형별로 허용값이 다른 컬럼):
  - 제품배송형: `발송완료` → `가이드전달완료` → `수령완료` → `업로드완료`
  - 현장방문형: `확정완료` → `가이드전달완료` → `방문완료` → `업로드완료`
- 업로드 기한 (날짜, D-day는 계산해서 표시)
- 업로드 링크
- 조회수, 인게이지먼트(좋아요+댓글 합계) — **수동 입력** (SNS API 자동 연동은 범위 밖, 아래 "제외 범위" 참고)
- `updated_at`

### `reports`
- `campaign_id` FK, 생성 시점 스냅샷 데이터 (JSONB: 캠페인 개요 + 지원자/관리시트 데이터), 사용자가 추가한 커스텀 섹션 (JSONB), `generated_at`

**관계 요약**: 캠페인 1:N 지원자, 지원자 1:0..1 관리시트행(최종선정된 경우만 생성).

## 핵심 화면/플로우

1. **캠페인 생성 & 사전조사**: 담당자가 캠페인 생성(이름/업체명/유형) → 사전조사 공개 링크 자동 발급 → 업체 담당자(외부 링크) 또는 에이전시 담당자(내부)가 질문틀에 답변, 막히면 "AI 도움받기"로 후속질문/추천 초안 제공 → 저장.
2. **신청폼 배포 & 지원자 리스트**: 사전조사 답변 기반 AI가 소개문구 초안 생성 → 담당자 검토/수정 → 게시 → 공개 신청 링크 활성화. 지원자는 표준 항목 + 캠페인별 커스텀 문항에 답변 → 제출 즉시 지원자 리스트에 반영. 지원자 리스트는 내부 대시보드 화면 외에 **별도 공유 페이지(`/applicants/[token]`)** 로도 제공되며, 이 페이지에서 최종선정/예비선정 액션을 수행할 수 있다(아래 3번). 또한 리스트 전체를 Excel/CSV 파일로 내보내기(다운로드) 할 수 있다.
3. **최종선정 / 예비선정**: 에이전시 담당자(내부 대시보드) 또는 업체 담당자(지원자 리스트 공유 링크, 로그인 불필요)가 각 지원자에 "최종선정" 또는 "예비선정"을 클릭할 수 있다. 누가 클릭하든 결과는 동일하게 즉시 반영된다. "최종선정" 클릭 시 `seeding_records` 행이 자동 생성되고 캠페인 유형에 맞는 입력 폼(배송정보/방문정보)이 노출된다. "예비선정"은 리스트 상태만 바꾸며 관리시트에는 반영되지 않고, 이후 필요 시 "최종선정"으로 승격할 수 있다. 미선정자는 상태만 `rejected`로 표시, 삭제하지 않음.
4. **관리시트**: 유형별 진행단계 체크리스트를 담당자가 갱신. 업로드 기한 입력 시 D-day 자동 계산. 업로드 링크/조회수/인게이지먼트는 수동 입력. 관리시트도 내부 화면 외에 **별도 공유 페이지(`/seeding-sheet/[token]`)** 로 업체 담당자에게 공유 가능하며, 공유 페이지는 **조회 전용**(수정은 에이전시 내부에서만)이다. 관리시트도 Excel/CSV로 내보내기 가능.
5. **결과보고서**: 관리시트에서 "보고서 생성" 버튼 클릭 시 현재 데이터 스냅샷으로 웹 리포트 생성. 기본 섹션: 캠페인 개요, 참여 인플루언서 리스트(이름/SNS링크/업로드링크), 성과 요약. 사용자가 커스텀 섹션 추가 가능. 다운로드 형식은 **PDF**와 **편집 가능한 PPT(.pptx)** 두 가지를 지원하며, PPT는 웹 리포트와 동일한 섹션 구성을 슬라이드로 단순 변환한 형태다.

## 인증 및 권한

- Supabase Auth 로그인 (이메일/비밀번호 또는 매직링크).
- 역할: `admin`, `staff` (2단계로 시작, 세부 조정은 추후).
  - **admin**: 전체 기능 + 사전조사 질문틀/신청폼 표준항목 등 설정 변경 + 팀원 초대·관리
  - **staff**: 캠페인 생성부터 보고서 생성까지 실무 전체 가능. 설정/팀원 관리 화면은 접근 불가
- 권한 체크 로직은 한 곳에 모아 추후 세분화가 쉽도록 한다.
- 공개 라우트(사전조사/신청폼/지원자리스트 공유/관리시트 공유)는 로그인 불필요, 캠페인별 고유 토큰으로만 접근 제어.
- 지원자 리스트 공유 페이지(`/applicants/[token]`)는 조회뿐 아니라 최종선정/예비선정 같은 **쓰기 액션**도 허용하는 유일한 공개 라우트다. 관리시트 공유 페이지(`/seeding-sheet/[token]`)는 조회 전용이다.

## 에러 처리 및 검증

- 공개 폼: 필수항목·동의 체크박스 미체크 시 제출 차단. 잘못되거나 비활성화된 토큰 접근 시 안내 페이지.
- 지원자 중복 제출: 동일 캠페인 내 SNS 링크 또는 연락처 기준 중복 감지 시 담당자에게 경고 표시(차단 아님).
- AI 어시스트 실패 시: 에러로 막지 않고 "AI 제안 실패 — 직접 입력해주세요"로 폴백, 수동 입력은 항상 가능.
- 관리시트/보고서: 소규모 팀 동시 사용 기준 — 낙관적 업데이트로 충분, 별도 동시편집 잠금 불필요.
- 최종선정/예비선정 액션: 에이전시(내부)와 업체(외부 링크) 양쪽에서 실행 가능하므로, 각 액션에 실행 주체(`agency` | `company`)와 시각을 기록해 나중에 "누가 언제 선정했는지" 추적할 수 있게 한다. 이미 선정된 지원자를 다시 클릭해도 에러 없이 현재 상태를 유지한다(멱등 처리).

## UI/디자인 시스템

브레인스토밍 중 만든 시안 비교 아티팩트(https://claude.ai/code/artifact/8763ee6a-203f-4f99-b815-f8db2005be84)를 기반으로 아래와 같이 확정한다. 실제 라이트/다크 모드 전환에 연동하며, 뷰어의 시스템 설정 또는 명시적 토글에 따라 자동으로 바뀐다.

- **다크 모드(기본값) — "Ops Console"**: 배경 `#0E1114`, 서피스 `#171B1F`/`#1E2429`, 텍스트 `#E8EDF0`, 액센트 오렌지 `#FF6A3D`, 보조 틸 `#35D0BA`. 폰트: 헤딩 "Big Shoulders Display"(대문자), 본문 "IBM Plex Sans", 데이터/숫자 "IBM Plex Mono"(tabular-nums). 모서리 반경 4px, 그림자 없음 — 방송/모니터링 콘솔 톤.
- **라이트 모드 — "Studio Board"**: 배경 `#F3F1F6`, 서피스 `#FFFFFF`/`#ECE7F2`, 텍스트 `#241B2E`, 액센트 라즈베리 `#D6336C`, 보조 바이올렛 `#7048E8`. 폰트: 헤딩 "Fraunces"(세리프), 본문 "Karla". 모서리 반경 14px, 소프트 섀도우 — 크리에이터 스튜디오 무드보드 톤.
- 두 모드 공통: 시맨틱 색상(success/warning/critical)은 액센트와 분리해서 정의, 카드형 레이아웃 + 좌측 사이드바 내비게이션(오버뷰/시딩/행사/SNS운영/전체일정), D-day와 진행률은 항상 tabular-nums로 정렬.
- 구현 시 이 값들을 Tailwind 테마 토큰(CSS 변수)으로 등록하고, `prefers-color-scheme` + 명시적 토글(`data-theme`) 둘 다 지원한다.

## 제외 범위 (이번 스펙에서 다루지 않음)

- SNS API를 통한 조회수/인게이지먼트 자동 수집 — 인플루언서 개인 계정 게시물은 공식 API로 임의 조회가 제한적이라 이번 범위에서는 업로드 링크 기록 + 수동 수치 입력까지만 다룬다. 자동화는 필요 시 별도 서브 프로젝트로 검토.
- admin/staff 세부 권한 커스터마이징 — 우선 기본 2단계로 시작, 필요 시 추후 조정.
- 서브 프로젝트 B(인플루언서 행사), C(SNS 운영), D(오버뷰/전체일정) — 각각 별도 스펙.
